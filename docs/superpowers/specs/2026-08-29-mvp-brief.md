# Intentionally Blank v0.1 - Minimal Playable Prototype

> Ryan's requirements brief, verbatim, 2026-08-29. The design that answers it
> is `2026-08-29-mvp-design.md`. (Release numbering is settled there; the
> "0.1.0" below predates the merged changelog in which 0.1.0 is the spec
> foundation.)

## Goal

Build the smallest possible playable version of **Intentionally Blank**.

This is a technical and UX proof of concept, not the beginning of the actual story.

The purpose is to prove that we can:

* display a text-adventure REPL in the browser
* accept typed natural-language commands
* interpret a few simple commands
* maintain minimal game state
* trigger events after player actions
* display a modal/popup interaction
* accept credentials
* transition to a final game-over state
* restart the game

Keep the implementation simple. Do not build systems we do not yet need.

---

# Opening

The player is sitting at a computer.

Present a simple atmospheric description such as:

> You are sitting in front of a computer.
>
> The cursor blinks patiently.
>
> You have the vague impression that something important is supposed to happen, although the computer seems unwilling to elaborate.

Then present the command prompt.

```text
>
```

---

# Basic REPL

The player should be able to type commands and press Enter.

The command and response should append to the transcript.

Support a handful of commands or semantic equivalents.

Examples:

```text
> say hello world

Hello, world.
```

```text
> ask jeeves the weather

Jeeves considers the matter.

"The weather is adequate."
```

This does **not** need real weather data.

Other simple commands may include:

```text
look
help
hello
who are you
time
weather
```

Feel free to include several amusing responses.

Unknown commands should receive a useful or funny fallback rather than throwing an error.

Example:

> The computer gives this considerable thought and ultimately decides it has no idea what you mean.

---

# Turn Counter

Maintain a simple count of meaningful player commands.

After approximately **3 to 5 commands**, trigger the next event.

Exact timing may vary slightly if that produces better pacing.

---

# Popup Event

A popup/modal appears.

It should feel like an unexpected system event.

Example:

> **ACCOUNT REQUIRED**
>
> Your complimentary Internet session has expired.
>
> Create an account to continue.

Provide username and password fields.

The correct credentials are:

```text
username: user
password: password
```

The player should be able to discover these either through an obvious hint or by experimenting.

For this prototype, do not make the credentials difficult.

The joke is that the security is terrible.

---

# Successful Login

When the player submits:

```text
user
password
```

show something like:

> ACCOUNT CREATED.
>
> Welcome, user.
>
> Your password security rating is: **catastrophic**.

Pause briefly or continue on interaction.

Then:

> There is a violent pounding on the door.

Then:

> The door bursts open.

Then:

> The Internet Police enter the room.

Then:

> You are under arrest.

Finally:

```text
GAME OVER
```

Optionally add a dry narrator line such as:

> In retrospect, "password" may not have been your finest contribution to information security.

---

# Game Over

Show:

```text
GAME OVER
```

and a clear:

```text
RESTART
```

control.

Restart should completely reset:

* transcript
* turn count
* modal state
* credentials
* game-over state

and return the player to the opening description.

---

# UX Requirements

Keep the interface extremely simple.

Recommended visual structure:

```text
INTENTIONALLY BLANK

--------------------------------

You are sitting in front of a computer...

> say hello world

Hello, world.

> _

--------------------------------
```

Requirements:

* keyboard-first
* Enter submits commands
* input automatically regains focus
* transcript scrolls naturally
* player input is visually distinguishable from game responses
* readable monospace or terminal-adjacent aesthetic
* responsive on desktop and mobile
* accessible modal behavior
* no unnecessary menus or navigation

Do not overdo the green-terminal aesthetic. This is a modern interface inspired by classic interactive fiction.

---

# Technical Philosophy

Use the architecture already being established in the repository.

For this prototype, the game should still begin respecting the intended long-term separation:

```text
PLAYER INPUT
     ↓
COMMAND / INTENT INTERPRETATION
     ↓
STRUCTURED GAME ACTION
     ↓
GAME STATE
     ↓
AUTHORED RESPONSE
```

However, keep the implementation proportional to this tiny prototype.

Do **not** integrate an LLM yet unless the existing architecture makes doing so trivial.

A simple deterministic parser with synonyms is sufficient.

For example:

```text
say hello world
say "hello world"
hello world
```

may all resolve sensibly.

---

# Minimal State

The prototype only needs state roughly equivalent to:

```text
turnCount
transcript
accountPromptTriggered
loggedIn
gameOver
```

Do not build the full production world model just to support this demo.

---

# Save System

A persistent save system is **not required for v0.1**.

The prototype is short enough that restarting is sufficient.

However, do not make architectural choices that prevent us from adding:

* autosave
* manual save
* load
* undo

later.

---

# Content Scope

This should take only a few minutes to play from beginning to end.

That is intentional.

Do not add the Badlands, notebook, family, data center, simulation story, or other main-game material yet.

This is our equivalent of:

> **Can we make the machine go?**

Once this feels good, we will begin building the actual opening room and game systems on top of the proven interaction model.

---

# Acceptance Criteria

v0.1 is complete when:

1. The game loads as a static browser application.
2. The opening text appears.
3. The player can enter commands into a REPL.
4. At least several commands produce authored responses.
5. Unknown commands fail gracefully.
6. The game tracks turns.
7. After several turns, the account modal appears.
8. `user / password` is accepted.
9. Successful login triggers the Internet Police sequence.
10. The game reaches `GAME OVER`.
11. Restart completely resets the experience.
12. The application can be deployed using the repository's intended GitHub Pages workflow.

Keep it small, polished, and funny.
